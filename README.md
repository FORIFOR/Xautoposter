# Xautoposter

**Xの反応を、発信の判断材料にするローカル分析アプリ。**

人気投稿の総数を眺めるだけでなく、時刻付きの実測から伸び方を計算し、同条件の通常投稿と比べ、反応の根拠を確認します。独立したアプリで、Launchloomのコード・DB・設定に依存しません。

P0の分析機能に加え、**自分の投稿 → 反応の観測 → 振り返り → 改善案**を記録する画面を追加しました。Xへの自動投稿・返信・DM・予約配信、LLMによる投稿文生成は未実装です。公開操作はXの画面で行います。

## 自分の投稿から改善する

Xへ公開する前に、[公開品質の基準](docs/PUBLISHING_POLICY.ja.md)で、単独で読める完成稿かを確認します。試験投稿や途中の観測報告はローカルに保存し、微修正した文を削除・再投稿して本番で試す運用は行いません。

左の **「自分の発信・改善」** を開きます。合成レーダーとは独立した、実際に使う自分の発信の記録です。初期データは空です。

1. アカウント、継続テーマ、届けたい価値、仮説、本文、根拠を入力。評価する指標と経過時間（1・24・72時間）を投稿前に決めて下書きを保存。
2. 本文をコピーするか「保存した本文をXで開く」。公式[Web Intent](https://docs.x.com/x-for-websites/web-intents/overview)へのリンクで投稿画面を開きます。アプリが投稿ボタンを押すことはありません。画像・文字数・投稿先をXで確認します。
3. Xで公開した後、実際の投稿URL・公開日時を登録。これは**利用者による申告**で、公開成功や所有アカウントを機械的に検証した状態ではありません。本文・仮説・評価条件はここで固定します。
4. Xで確認した累積指標と観測日時を「反応を保存」。空欄は不明。返信・引用の抜粋には出典URLと確認時刻を残します。この画面は手動観測で、既存の公式APIデータとはまだ自動同期しません。
5. 指定した経過時間の実測値を比較。許容差は経過時間の15%（最小5分・最大30分）。同じアカウント・テーマ・形式・評価指標・経過時間、投稿日±7日の投稿が比較対象です。該当時刻の観測がなければ「判定不能」。総数から過去を逆算しません。
6. 観測した学び、根拠、別の説明、次に変える点を記入し「振り返りと根拠を保存」。使った観測と比較レポートを固定します。
7. 「この振り返りから改善案を作る」で前回と紐づく新しい下書きを作成。変更点は引き継ぎ、本文は空から書き直します。公開後の同じ経過時間で、改善元との差を確認できます。

下書き・公開URL登録・観測中・振り返り保存済みを区別します。新しい観測を追加すると古い振り返りは再確認が必要になり、再保存まで改善案作成を停止します。同時編集の上書き、重複URL、矛盾する同時刻指標を拒否。変更履歴と全記録のJSON出力も利用できます。

比較は無作為化した実験ではありません。露出・投稿時刻等の影響が残るため、数本の結果だけで変更の因果効果やバズの再現性は保証しません。投稿先とテーマの確定、実際の公開、反応が蓄積するまでの観測が、運用開始に必要です。

## 起動

Python 3.11以上。動作確認環境はmacOS / Python 3.14.6です。

```sh
cd /Users/shuhei/Projects/Xautoposter
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m xautoposter
```

[http://127.0.0.1:8790](http://127.0.0.1:8790) を開きます。初期状態は空のワークスペースです。**「合成データで試す」**から、APIキー・外部通信なしで試せます。この作業環境には依存ライブラリを導入済みです。

```sh
# 別のポート・保存先を使う場合
.venv/bin/python -m xautoposter --port 8791 --data-dir ./data-research
```

SQLiteは既定で実行ディレクトリの `data/radar.sqlite3` に保存します。保存先は `XAUTOP_DATA_DIR` でも指定できます。1プロセスで起動してください。サーバーは127.0.0.1にのみバインドします。

## 画面で試す

1. **急上昇レーダー** → 「合成データで試す」。架空の3テーマ、元投稿21件、返信・引用8件、89観測を読み込みます。固定の過去データで、最新のXの分析結果ではありません。
2. 話題カードの「投稿を見る」で絞り込み、投稿を開きます。
3. **投稿分析**で指標推移、比較対象のID・観測時刻・経過時間、構成、反応の抜粋、仮説を確認します。最初の「セキュリティの優先順位」投稿には本人の過去投稿4件との比較と、返信・引用8件があります。
4. 「分析メモ」に次の検証を書き、「分析とメモを保存」。**分析ライブラリ**から再表示できます。再読み込み・アプリ再起動後も残ります。
5. 「保存時の分析を見る」で、保存時点の観測・比較条件・仮説を再表示。「分析JSON」で出力できます。保存の更新は、その時点の観測から再計算して置き換えます。
6. ライブラリの「保存済みだけ」を解除すると通常の反応の投稿も表示。構成で絞り込み、投稿詳細の高反応群／通常群の特徴表で比較できます。

「観測不足のサンプル」では、1時点・指標欠損・形式不明のため、速度・初速・通常比を判定不能として表示します。

## 公式X APIを使う

1. **収集設定**でBearer Tokenを入力します。Tokenはサーバーのメモリにのみ保持し、DB・ブラウザストレージへ保存しません。アプリを再起動すると画面で入力したTokenは消えます。代わりに起動時の環境変数 `X_BEARER_TOKEN` を使えます。
2. キーワード／検索式、`@account`、投稿URL／IDのいずれかで収集条件を保存します。条件名が登録テーマになります。複数条件を同じテーマで扱う場合は同じ名前にします。テーマの一致は手動指定で、意味による自動クラスタリングではありません。
3. 1要求・日次の投稿数、更新間隔、日次／月次予算、推定単価を設定し、「すべてのAPI収集を停止する」を解除して保存します。
4. 「今すぐ収集」。新着は通常投稿も含む**新着順**で取得。初回は直近24時間、次回は `since_id`。取得上限時はカーソルと元の時間窓を保存し、次の要求で続きを読みます。
5. 検索条件には、本文検索とは別に**件数APIで終了済み6時間の時間別件数**を取得します。本文標本数と話題全体の件数は別表示。検索式の異なる件数は重複し得るため合算しません。
6. 続けて観測したい投稿を分析ライブラリに保存。「保存した投稿の指標を再観測」、または投稿詳細の「指標を再観測」で追加時点を取得します。
7. 投稿詳細の「返信・引用を取得」で反応の標本を追加。返信は直近7日内の会話検索、引用は引用取得APIの1ページ。未取得範囲は完全取得と表示しません。

定期取得は条件ごとにONにできます。保存済み投稿だけの定期再観測も別に選択可能。**アプリが起動している間だけ**、単一の収集処理が動きます。停止設定と間隔は手動取得にも適用します。APIへの書き込み権限・書き込み経路はありません。

認証・権限・課金エラー、429、タイムアウトは履歴に記録します。自動HTTPリトライはありません。429は応答の再開時刻まで停止。費用の結果が不確実な要求は、最大費用の予約を保持します。次回の定期収集は、設定された間隔に従う別の取得として扱います。

ローカル予算は推定です。同日の重複課金排除は織り込まず保守的に計算。実際の権限・単価・課金額・請求上限はDeveloper Consoleが正本です。**実装と模擬応答の検証は済んでいますが、実キーでの接続は未検証です。**

## CSV / JSON取り込み

「データを取り込む」からファイルまたはテキストを指定します。4MBまで、1取り込み5,000投稿・20,000観測まで。見本のCSV／JSONも画面からダウンロードできます。**見本はすべて合成データ**です。

同じデータセットを選択して追加すると、同じ投稿IDの観測履歴に追記します。同じID・同じ観測時刻・同じ指標は重複排除。値が矛盾する場合は取り込み全体をロールバックし、元の観測を上書きしません。公式API・取り込み・合成のデータセットをまたぐ比較はしません。

CSVは1行＝1時点。指標の空欄・`null`・`NA`は不明です。

```csv
id,author_id,text,topic,lang,media_type,created_at,observed_at,like_count,retweet_count,reply_count,quote_count,bookmark_count,impression_count
123,456,観測する投稿本文,ログの分析,ja,text,2026-09-12T00:00:00Z,2026-09-12T01:00:00Z,10,2,1,0,,
123,456,観測する投稿本文,ログの分析,ja,text,2026-09-12T00:00:00Z,2026-09-12T02:00:00Z,30,5,2,1,,
```

JSONの最小例（数値と本文は形式説明用）:

```json
{
  "provenance": "synthetic",
  "posts": [{
    "id": "example-1",
    "author_id": "example-author",
    "text": "形式を説明するための架空の投稿。",
    "topic": "ログの分析",
    "lang": "ja",
    "media_type": "text",
    "created_at": "2026-09-12T00:00:00Z",
    "snapshots": [{
      "observed_at": "2026-09-12T01:00:00Z",
      "like_count": 10,
      "retweet_count": 2,
      "reply_count": 1,
      "quote_count": 0
    }]
  }],
  "counts": [{
    "topic": "ログの分析",
    "query": "ログ lang:ja -is:retweet -is:reply",
    "start": "2026-09-12T00:00:00Z",
    "end": "2026-09-12T01:00:00Z",
    "observed_at": "2026-09-12T01:01:00Z",
    "count": 80,
    "complete": true
  }],
  "complete": false,
  "scope": "形式説明用の架空データ。本文標本と件数全体は別。"
}
```

`kind`は `original`（既定）／`reply`／`quote`。返信・引用には `parent_id` を指定します。元投稿が未登録でも取り込めますが、対応する投稿詳細で反応を表示するには元投稿も必要です。

日時はタイムゾーン付きISO形式。未来の観測、投稿作成前の観測、負の指標は拒否。言語不明 `und`、媒体不明 `unknown` は同条件比較から除外します。

## 計算と限界

- **反応数**：いいね＋リポスト＋返信＋引用。いずれかが欠損なら合計も不明。ブックマーク・表示回数は独立表示。
- **速度**：直近2観測の反応差分÷実際の時間差。途中を補間せず、累積総数から過去の初速を逆算しません。1指標でも減少した区間は速度を判定不能にします。
- **加速の表示**：直近2区間の平均速度を比較。3時点以上が必要。瞬間的な加速度ではありません。3時間以上古い観測は「過去の観測」と表示します。
- **比較**：同じ登録テーマ・言語・媒体形式、投稿日±7日、投稿後の経過時間±15%（最小5分・最大30分）。対象の最終観測より後の観測は使いません。投稿者本人の過去標本が3件以上ならその中央値、それ以外は比較集団5件以上。中央値5反応未満の倍率は表示しません。
- **構成比較**：対象を含め6件以上の同条件標本から、反応上位1/3と下位1/3（各群最低2件）を比べます。両群の反応値が重なる場合は差を判定しません。下位群は標本内の「通常群」であり、X全体の平均ではありません。
- **文章・反応**：P0はローカルのルール解析。LLMを呼び出していません。冒頭・結び・対比・問い・実験・具体例等の検出、返信／引用の仮分類、比較に基づく仮説と別の説明を出します。皮肉・否定・複雑な文脈は人の確認が必要です。
- **根拠**：投稿ID、観測時刻、比較条件、標本数、分類に使った抜粋を確認できます。元投稿自体の事実確認はしません。分類比率を世論・全閲覧者の支持率へ換算しません。
- **本文変更**：同じIDの本文・属性更新は旧情報を履歴へ退避。構成が変わった投稿は通常比の比較から除外します。作成時刻・投稿者・返信関係の矛盾は拒否します。

## P0の境界

自動トピッククラスタ、LLMの高度な文章解析・投稿案生成、自動配信、外部サイトへの流入・成約計測は含みません。自分の投稿と手動観測の循環は上記の追加画面で扱います。地域別トレンドAPIはこのP0では未接続です。登録した分野の検索と件数系列をレーダーの入口にしています。

Xの削除・非公開化の自動追随、長期保管の運用、複数ユーザー／複数サーバー、OSサービスとしての常駐は未実装です。取り込み全件をメモリに読み込む小規模ローカル運用のP0で、大規模データの性能は未検証です。

参照したX公式資料（実装時確認：2026-09-13）：[Search quickstart](https://docs.x.com/x-api/posts/search/quickstart/recent-search)、[Metrics](https://docs.x.com/x-api/fundamentals/metrics)、[Counts](https://docs.x.com/x-api/posts/get-count-of-recent-posts)、[Pricing](https://docs.x.com/x-api/getting-started/pricing)。
