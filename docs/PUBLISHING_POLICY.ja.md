# Xに残す投稿の基準

2026年9月14日のユーザー指示に基づく運用方針。Xは後から読み返しても役立つ完成稿を残す場とし、検証・試作・観測ログはXautoposter内で管理する。

## 公開前に満たすこと

1. 読者が単独で読んで理解でき、具体的な知識・手順・実例のいずれかを持ち帰れる。
2. 製品の機能・実績・数値は確認した根拠に対応している。仮例、合成データ、意見、未検証の内容は明確にする。
3. 未完成の文、テスト文、操作ログ、単なる取得報告、AIへの指示や内部メモを含まない。
4. 直近の投稿と比べて内容の重複がなく、アカウントの発信テーマにつながる。微修正の別稿を連続して公開しない。
5. 投稿先、本文、添付、紹介先の動作を公開前に確認する。UI操作の練習はローカルで行い、本番投稿の成功確認は必要最小限にする。

自分の失敗や開発過程を扱うこと自体は問題ない。分析を終え、読者が応用できる学びと根拠にまとめてから公開する。単に「何本投稿した」「表示が何件だった」「次に計測する」という作業報告だけでは公開しない。

## 公開後の扱い

- 表示やいいねが少ないだけでは、不適切な投稿と判定しない。
- 通常の改善は次の完成稿へ反映する。削除・再投稿をA/Bテストの代わりに繰り返さない。
- 誤情報、未完成、操作テスト、重複などの問題がある場合は、対象URL・理由・修正または削除の扱いを具体化する。プラットフォーム上の不可逆な削除には、その対象に対する必要な確認を行う。以前の別URLへの承認を流用しない。
- 元本文、実際の観測時刻と指標、整理の理由はローカルに残す。良かった結果だけを残して分析結果をゆがめない。
- 削除した投稿は計測対象から外し、未観測の数値を補わない。

## 発信の目標

ユーザーが「いいねがたくさんつくような投稿をする」と明確化したため、今後の原稿は投稿後24時間のいいね数を主な評価指標にする。表示回数・返信内容・フォロワー増減は、結果を解釈する補助情報として記録する。既に公開した投稿の事前設定や観測履歴は書き換えず、新しい目標をいつ設定したかを区別する。完成稿を読者に届けることを優先し、反応を増やすための試験投稿や重複投稿は行わない。

## 9月14日の内容評価を受けた編集基準

読みやすさ、画像の見栄え、事実を誇張しないことに加え、次を公開前に確認する。

- 読み手が読んだ前後で何を新しく理解し、判断・行動に使えるかを一文で説明できる。
- 誰が、どの具体的な発見・問題・答えを他人に渡したくなるかを説明できる。一般論に架空例を添えただけで合格としない。
- 開発成果なら、本人の実装・入力と出力・失敗条件・比較結果から題材を選ぶ。「実装しました」を付けるだけでは読む理由にならない。すべての投稿に数値を要求する意味ではなく、具体的な観察や根拠のある意見も扱える。
- よい数字だけを抜き出さない。検知対象の範囲、比較条件、合成データか実データかを保ち、別のルールや測定単位を混ぜない。

ユーザーからの内容の評価を、露出不足や観測期間の短さだけで退けない。反応数から判断できないことと、原稿の編集上の弱さは分けて扱う。今回の見直しは `docs/EDITORIAL_REVISION_2026-09-14.ja.md` に記録した。
