# 実測から次の検証案へ

`python -m xautoposter` で起動し `/learning` を開く。従来の分析・下書き・公開URL登録画面は `/research` で使える。データ形式と既存データは維持する。

1. 従来画面の「自分の発信・改善」で下書き・公開URLを登録する。
2. 収集設定でAPIキー、予算、全体停止状態を確認する。
3. `/learning` で観測間隔と次の検証案の自動作成を選び、定期観測を開始する。
4. GET専用の既存コレクターが公開投稿を取得する。本文・ID・投稿者IDの一貫性を確認し、出典を保持して同期する。本文が短縮URL等で異なる場合も自動で一致扱いしない。
5. 事前指定した経過時間の実測が揃うと、自動作成を許可している場合のみ次の検証案を1件作成する。0は実測値として扱う。欠測からの補間はしない。
6. 観測目標に到達すると定期取得を停止する。次の案には本文を自動捏造せず、根拠と変更仮説を保存する。人が本文を執筆し、Xで公開する。

手入力とAPI観測は別々に残す。比較は同じ出典・指標定義・投稿者・テーマ・形式・経過時間を使う。公開投稿の一致確認はアカウント所有権の証明ではない。次の案は公開権限を持たない。

API同期は反復しても重複しない。矛盾・上限・同時編集では元データを保つ。次案と親の関連は一つのSQLiteトランザクションで保存する。新しい観測は保存済み振り返りを要再確認にする。過去の根拠は書き換えない。

既定は停止。課金上限・429・取得間隔は既存のCollectorが管理する。アプリの稼働中のみ実行し、停止・スリープ中を補完しない。常時運用する場合は自分の常時起動ホストで単一プロセスとして実行する。

実キー、課金、数日間の継続運転は別途検証が必要。この変更にLLMへの送信、Xへの投稿・返信・DMは含まれない。
