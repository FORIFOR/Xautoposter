# 根拠を読み、完成原稿を提案する

従来のルール分類・数値比較を置き換えず、未公開の検証案に対してLLMが読者の疑問、伝える価値、変更の狙い、別の説明と完成原稿を提案する。出典IDと連続引用を元資料に照合する。これは引用の存在確認であり、事実の正しさや解釈の妥当性の証明ではない。

## サーバー設定

起動前に環境変数を設定する。秘密値はGitやチャットへ貼り付けない。

```sh
export XAUTOP_LLM_ENABLED=true
export XAUTOP_LLM_MODEL='<利用可能なResponses/JSON Schema対応モデル>'
export XAUTOP_LLM_DAILY_LIMIT=10
# OPENAI_API_KEYはOSの秘密設定または環境変数から渡す
python -m xautoposter
```

既定は無効。モデル名とAPIキーの両方が必要。日次上限はUTCで失敗/中断を含む要求数を数える。金額の上限ではないため、プロバイダー側でも請求予算を設定する。プロセスに.envを自動読み込みする変更は行っていない。設定ファイルを使う場合は既存の起動方法で環境変数へ渡す。

## 使う

`/learning` で未公開の検証案を選ぶ。原稿・根拠・改善元の文章をOpenAIへ送りAPI費用が発生することを許可し、「LLMで原稿を生成」を押す。原稿と解釈・注意点を確認し、問題がなければ「この原稿を採用」。採用後もX上では未公開。事実・文脈・文字数・添付物を確認し、Xの画面で人が公開する。

同じ検証案の版・モデルへの要求は再送しない。元の原稿を編集して版を変えることで新しい生成要求を作れる。生成中に元の原稿や改善元の観測が変わった場合、古い結果を採用して上書きすることはできない。生成結果は別テーブルへ保存され、採用するまで原稿本文を変更しない。

本文は日本語/URLの重みを保守的に数えた280単位以内。絵文字の結合などは長めに数えるため、Xと完全一致する文字数計算ではない。公開時の最終確認はXで行う。

## 権限と検証

LLMの接続先は固定のOpenAI Responses APIで、toolsなし・store=false。モデルにネットワークアクセス、コレクターの操作、数値の上書き、Xへの送信権限を与えない。実際の保存・保持条件はプロバイダー契約に従い、store=falseを完全なログ不保持の保証とは扱わない。

入力32KB・応答512KB・出力4000トークン・タイムアウト90秒。URLの取得、HTTPリダイレクト、環境プロキシ、自動HTTPリトライは行わない。応答拒否/不正JSON/出典不一致/プレースホルダー/過大本文では元の原稿を保持して失敗を記録する。

テストは生成器を模擬し、原稿の採用、版競合、出典検証、日次上限、HTTP権限境界を検証する。実モデルの品質・費用・稼働は別途確認が必要。Xへの投稿・返信・DMの自動実行は実装していない。
